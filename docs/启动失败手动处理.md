# 启动失败手动处理

给「双击 `start-macos.command` / `start-windows.bat` 之后窗口里出现红色字」的你。
不需要懂编程，从上往下找到窗口里那句话，照着做就行。

> 一句话原则：**这个项目只会动它自己那个文件夹**。任何一步让你「删文件」，都只会删项目文件夹里的东西，
> 不会碰你的文档、照片、浏览器记录。会话记录（聊过的内容）本来就不落盘，重启后 B 的旧链接一定失效。

---

## 0. 先做这三件事，80% 的失败就好了

1. **关掉窗口，重新双击一次启动脚本**。很多失败是网络抖一下、或者上次没退干净。
2. 还是不行 → **把整个项目文件夹换一个位置**：放到「文稿」或桌面以外的一个简单路径下，
   比如 Mac 的 `/Users/你的用户名/aiwindow`、Windows 的 `D:\aiwindow`。
   路径里带中文、空格、或者放在 iCloud / OneDrive / 坚果云这类会同步的盘里，都可能出问题。
3. 还不行 → 看下面按**红字内容**分类的表，或者直接把 `logs/` 里最新的那个 `.log` 文件发给作者。

---

## 1. 第一次双击被系统拦住（这是正常的）

### macOS：「无法打开，因为它来自身份不明的开发者」

本项目没有买 Apple 的开发者证书，所以第一次一定会被拦一次：

1. 打开「访达」，进入项目文件夹；
2. **右键**点 `start-macos.command`（不是双击）→ 选「打开」→ 弹窗里再点「打开」；
3. 之后就可以正常双击了。

还不行就再打开「系统设置 → 隐私与安全性」，往下拉会看到一条被拦的记录，点「仍要打开」。

### Windows：蓝色「Windows 已保护你的电脑」

点「更多信息」→「仍要发布」。同理，因为项目没有代码签名证书。

## 2. 按窗口里的红字对号入座

窗口里最后那几行就是原因，格式固定是「启动失败：xxx」+「怎么办：xxx」。
先照「怎么办」那句做；下面是更详细的版本。

| 窗口里出现的字 | 什么意思 | 你该怎么做 |
|---|---|---|
| `网络连接失败，暂时无法准备运行环境` | 下载运行环境时断网了 | 换网络（手机热点也行）后重新双击。**不要**手动去下别处的 Node 塞进来，见第 3 节 |
| `下载的 Node 与清单校验值不一致，已删除，不会解压执行` | 下载的文件被网络中间人改了 / 下坏了 | 换网络重试。这条是保护你的，反复出现说明你所在的网络在篡改下载 |
| `8787 端口被别的程序占着` / `8788 端口被…` | 有别的程序在用这个项目要用的端口 | 窗口里会写出**是谁**（程序名和进程号）。关掉那个程序，再重新双击。见第 4 节 |
| `这个项目的本地服务已经在跑了` | 你已经双击过一次了 | 直接去浏览器里刷新 A 工作台那个标签页就行。要重启就先跑一次停止脚本（`stop-macos.command`）。⚠️ 刷进去如果写着「本机控制会话已失效」，那是登录态过期，见 §6.1 |
| 浏览器里（不是窗口里）写着「**本机控制会话已失效**」 | 服务在跑，但你是从书签/历史/旧标签页进来的，那条一次性引导地址已经用过了 | 见 §6.1。不是公网坏了，不是重装的理由 |
| 别人（或另一台电脑）打开链接，只看到一行 `404 Not Found` | 通道是通的，请求已经到了你这台电脑 —— 他打开的是**通道地址**，不是那条带 `/s/…` 的会话链接 | 见 §8。把会话卡片上点「复制」得到的**整段**发给他（工作台平时已经不显示那行裸域名了） |
| `另一个启动过程正在准备环境` | 两个启动窗口同时在准备 | 只留一个窗口，等它跑完（第一次要几分钟）。实在卡住见第 5 节 |
| `构建产物不全` | 项目文件不全 / 上次构建被打断 | 先跑一次第 5 节的「彻底重来」 |
| `这台机器的平台 xxx 不在支持列表内` | 系统不是 macOS(Intel/Apple 芯片) 或 Windows x64 | 这台机器本项目没把过关，找作者 |
| `找不到 runtime-manifest.json` | 你拷的是零散文件，不是完整文件夹 | 重新拿完整的项目文件夹，压缩包里要**整个目录**一起解压 |
| `启动前自检没通过：…` | 目录结构被动过（改名、少文件夹） | 红字会点名是哪一项。多半是 `增加ai味skill` / `深度思考反推skill` 这两个文件夹被改名或删了，改回原名 |
| `本地服务起来了但健康检查没过` | 服务启动了但没答话，通常是权限/磁盘问题 | 看红字里点名的那个日志文件的最后几十行；同时跑第 5 节 |
| `退出码 3 / 4 / 5 / 6 / 7 / 8` | 上面这些类型的编号 | 对照表；把编号 + 日志一起发给作者最快 |

## 3. 「换镜像下载」（确认是网络问题后用）

脚本要下的东西**只有两样**，都在项目自己用，装完就写在项目文件夹里，不会装到系统里：

- 项目专用 Node：`v24.18.1`
  - Apple 芯片的 Mac：`node-v24.18.1-darwin-arm64.tar.gz`
  - Intel 的 Mac：`node-v24.18.1-darwin-x64.tar.gz`
  - Windows：`node-v24.18.1-win-x64.zip`
  官方地址是 `https://nodejs.org/dist/v24.18.1/` 下面这几个文件
- 公网隧道组件 cloudflared：`2025.4.2`，在
  `https://github.com/cloudflare/cloudflared/releases/download/2025.4.2/` 下面

如果官方地址在你那儿很慢或下不动，可以让它**从镜像下载**（只换主机名，校验值不变）。
打开「终端」（Windows 用 PowerShell），进入项目目录后执行：

```
AIWINDOW_NODE_BASE=https://npmmirror.com/mirrors/node node scripts/bootstrap.mjs
```

（已经装好过一次的机器，这条一般不需要。）

**必须核对校验值**：校验值写死在项目根目录的 `runtime-manifest.json` 里，用文本编辑器打开就能看，
对应平台的 `sha256` 那一串。手动下载的文件可以用下面命令算：

Mac：`shasum -a 256 文件名`　　Windows：`Get-FileHash .\文件名 -Algorithm SHA256`

算出来要和清单里**一模一样**（不分大小写）。不一样就删掉，别用。

> 红字里那句「下载卡住了（30 秒没有新字节）」不是报错报错了，是它主动停下来的：直连被限速时
> 与其让你干等半小时，不如停下来告诉你换镜像。
>
> 手动下载下来的文件**不能**靠「扔进 `.runtime/download/`」让脚本认——脚本每次都会重新下载并自己校验，
> 那个目录只是它临时放文件的地方。手动核对的意义在于判断「是官方包被改了，还是你的网络在篡改下载」。
>
> 这个项目**没有**「跳过校验」这个选项，这是故意的：那个开关一旦被允许，别人在路由器上做手脚
> 就能把恶意程序塞进你的电脑。也别去改 `runtime-manifest.json` 凑数——
> 如果清单里你那个平台的 `sha256` 是 `null`，说明这一版项目没为那个平台把过关，脚本会直接拒绝下载，
> 这时候只能找作者补（工具是 `coding/scripts/gen-runtime-manifest.mjs`）。

## 4. 端口被占用

### 先看清是哪种

- 红字里写了程序名 → 就是那个程序在用。关掉它最省事（比如你正好开着另一个也用 8787 的开发服务）。
- 红字只写「被别的程序占着」、没写名字 → 用下面第一条命令看看是谁。

macOS（打开「终端」，粘贴执行）：

```
lsof -nP -iTCP:8787 -sTCP:LISTEN
```

Windows（PowerShell）：

```
Get-NetTCPConnection -LocalPort 8787 -State Listen
```

### 不想关那个程序？改端口

用文本编辑器打开项目根目录的 `.env.example`，找到这两行：

```
LOCAL_PORT=8787
PUBLIC_PORT=8788
```

改成别的数字（比如 `8887` / `8888`，两个都改，别改成一样的），保存，重新双击启动。
B 的链接会自动跟上，不用你去改别的地方。

**这个项目不会替你强行关掉任何程序。** 需要你手动关，或者改端口。

## 5. 彻底重来（不丢你自己的设置）

按这个顺序做，每做完一步就可以试一次重新双击：

1. 先双击 `stop-macos.command`（Windows：`stop-windows.bat`）；
2. 删掉项目根目录的 `logs` 文件夹（只是历史日志）；
3. 删掉项目根目录的 `.runtime` 文件夹 —— **这一步会让它重新下载运行环境和依赖，需要几分钟到十几分钟**；
4. 还是失败 → 连 `coding/node_modules` 和 `coding/dist` 一起删掉，再双击启动（它会自己重装重构建）。

**不要删**这些，它们是你自己的东西：

- `.env.local`：你的模型 key、你的偏好设置都在这里；
- `config/skills.json` 和 `增加ai味skill`、`深度思考反推skill` 两个文件夹：Skill 内容；
- `coding/data/`：SQLite，里面只有会话元数据与你的设置，聊天正文不存。

删错了也不怕：这些文件都在上面这几个位置，重新填一次 key 就能用。

## 6. 起来了，但浏览器没自动打开工作台

正常。有的机器不让脚本唤浏览器，这时它会**把地址印在窗口里**。

- 找窗口里那行 `一次性引导地址：http://127.0.0.1:8787/api/local/bootstrap/…`
  → **完整复制**粘贴到浏览器地址栏，回车。它只能用一次，成功后会把你带进工作台；
- 这一条地址过期/用过了，就直接访问 `http://127.0.0.1:8787/`：
  如果之前那次引导已经换过 Cookie，会直接进工作台；如果没换过，会让你重新走一次引导；
- 一定要用 `127.0.0.1`，不要用 `localhost`：登录凭证是绑在 `127.0.0.1` 上的，
  换写法就等于换了一个浏览器身份，会出现「看着像登录了但什么都读不到」。

### 6.1 页面能打开，但上面写着「本机控制会话已失效」

这是**最常见**的一种「看起来坏了」：窗口里一切正常、服务好好在跑，但你是从浏览器历史记录、
书签、或者昨天那个旧标签页里打开的工作台 —— 那一条一次性引导地址只能用一次，用过了就没了。

它长这样（出现在工作台最上面那一块）：

> 本机控制会话已失效：这条页面是旧的登录态。回到启动窗口里那条一次性引导链接重新打开
> （它只能用一次；找不到就重新双击启动脚本，会给你一条新的）。

按这个顺序做：

1. **回启动窗口**，找到那一行 `一次性引导地址：http://127.0.0.1:8787/api/local/bootstrap/…`，
   **完整**复制到地址栏回车（只复制一半也是这个失效结果）；
2. 窗口已经关了 → 先跑一次 `stop-macos.command`（Windows：`stop-windows.bat`），再重新双击启动。
   不先停止就重新双击的话，它会告诉你「已经在跑了」，而**不会**再给一条新的引导地址；
3. 进去以后别收藏 `http://127.0.0.1:8787/` 这个裸地址：每次启动都是一条新的引导地址，
   裸地址不带凭证，下次打开就是这个提示。要收藏就收藏进去之后的工作台页，
   而且只在**同一次启动期间**有效。

两个容易误判的地方：

- 这句话**只说明本机这一层的登录态没了**，不代表公网链接坏了 —— B 那边该能打开的还是能打开。
  真坏了的话，公网那一行会写「公网连接中断」「公网通道不可用」这类字，不是这一句。
- 地址栏写着 `127.0.0.1` 还一直看到这个提示：确认你没写成 `localhost`（见上面最后一条）。

## 7. 工作台开着开着不动了

- **关掉那个终端窗口就是退出**（这是设计：不留后台进程）。重启会是一个全新的开始，
  原来发给别人的 B 链接会失效，这是预期行为（PRD §4「不留痕」）。
- 公网链接断了：超过 15 秒连不上，进行中的会话会统一结束并显示「连接中断」。
  这不代表你的电脑坏了，通常是手机热点切换 / 隧道抖动。
- 卡在「公网连接中断，正在自动重连」不动：现在它**会自己收手**了 —— 地址反复失效到几轮之后会转成
  「公网通道不可用」，不会一直重连。这一步是故意停的：每次重连都会换一个新域名，
  把你已经发出去的那条链接彻底作废，**一直换比停下来更坏**。
- 看到「公网通道多次重连失败」或「公网地址反复失效」：点那个位置上的**「重试」**按钮（按钮字样随状态变，
  不可用时显示的就是「重试」，没有「重新连接」这个按钮）。连着几次都这样，就在设置页改走「本机地址」那条，
  让 B 和你连同一个 Wi-Fi 后用它。临时公网地址本来就不是稳的。
  ⚠️ 这种状态下点「再验一次」没用 —— 它只是重新检查已有的地址，而这时已经没有地址可检了。
- 提示「有地址但本机验证不通」时**不要**先去点「换一条链接」：域名一变，发出去的链接全死。
  先点「再验一次」；手机热点下常用的是自己手机能打开、只是你这台电脑 DNS 解析不通。
- **刚启动完就建窗口，复制按钮是灰的**：这不是坏了。启动后公网地址需要 20~70 秒才能建好并验证，
  这期间卡片上会写「正在建立 / 还没验证」。**同一个窗口不用重建**，地址一验通按钮自己就亮了。
  想马上能用：等面板上出现「验证可访问」再点「创建新会话」。
- 卡片上写的是 `http://127.0.0.1:8788/...`：这条**只有你这台电脑打得开**，发给朋友注定不行（另见 §8）。
  上面那句「还没有可用的公网地址」会告诉你该点哪个按钮。
- 「处置正文」或「深度反推」按钮转圈很久或报错：那是你自己的模型 key 那边的问题（余额、限流、模型名写错），
  启动脚本这一层不会管这件事。看 A 设置页里的提示，或跑 `coding` 里的模型连通性自检。

## 8. 另一台电脑打开你发出去的链接，页面说打不开

**先分清一件事：对方打开的不一定是「链接」。** 能分享的只有**会话卡片上点「复制」**拿到的那一整段，
结尾一定带 `/s/` 加一串字母数字。工作台上的公网那一行**平时不显示通道地址**（那一行没有标题，只有状态词加一两个按钮）
（它就是为了让 A 不误抄）；只有本机没验通时才会亮出来一行，并且标着「通道地址，不是要发给 B 的链接」。
所以对方看到 404 时，多半是从书签/浏览器历史里点了旧地址，或者复制时尾巴被截断了。

看对方屏幕上是什么样子，就能判断卡在哪一步：

| 对方看到的 | 意思 | 你该做什么 |
| --- | --- | --- |
| 白底一行 `404 Not Found` | 请求**已经到达你这台电脑**了（通道是通的），只是他打开的是通道地址，或者链接被截断了 | 让对方用卡片「复制」出来的**整段**，别手打域名；从聊天软件里复制时注意别丢掉换行后的尾巴 |
| Cloudflare 的花页，写着 **530** / `Origin Error` | 那个域名已经不归你的隧道了 —— 你重启过，或地址换过 | 重新建一条会话发过去。旧链接救不回来，重启对方电脑也没用 |
| Cloudflare 的花页，写着 **502**，或浏览器说「连接被重置 / 无法访问」 | 你这边的服务或隧道当时不在（窗口关了、电脑睡了、网络断了） | 重新双击启动脚本，等工作台写「验证可访问」再发新链接 |
| 页面显示「此链接无效，请确认地址是否正确。」 | 域名对、服务也在，但 `/s/` 后面那串代号不存在：复制不完整，或这条会话已经结束 | 重新复制一次；还不行就点「创建新会话」再发 |
| 浏览器说「无法访问 / 证书错误 / 找不到服务器」，而你自己能打开 | 对方那侧的网络不放行（公司内网、校园网关、代理） | 让对方换手机热点试一次，一改就知道 |

自己这边还能对一眼日志：`logs/` 里最新那个 `.log`，看有没有 `link opened`。
只有 `link created` 而没有 `link opened` → **对方根本没点到**；
`linkRef` 前 8 位对得上，就是同一条链接（怎么看日志见 §9）。

> ⚠️ 一个容易做的错事：**不要为了「再试一次」去重启启动脚本**。每重启一次就换一个域名，
> 你之前发出去的所有链接当场作废。这种情况该让对方刷新，而不是你重启。

## 9. 找作者帮忙时，请带上这些

1. 窗口里最后 5~10 行（截图或复制都行），尤其是有没有「退出码 N」；
2. `logs/` 里**最新**那个 `.log` 文件（名字形如 `run-2026-09-11T13-44-27-861Z.log`）；
3. 你的系统与机器：macOS 版本 + Apple 芯片还是 Intel；Windows 版本；
4. 一句话：这次是第一次跑，还是之前跑通过。

日志里不含你的模型 key、不含聊天内容，也**不含完整的会话链接**（只有前 8 位代号），可以放心发。

怎么自己先看一眼：每个窗口会有两行相关记录，同一个 `linkRef` 就是同一条链接。

```
link created  {"linkSource":"tunnel","linkRef":"e247606f","tunnelStatus":"ONLINE"}
link opened   {"linkRef":"e247606f"}
```

- 只有 `created`、没有 `opened` → 对方根本没点到（链接没递到、或递到的是别的机器）。
- `linkSource` 是 `local-dev` → 你发出去的是本机地址，别人必然打不开（见 §7 最后两条）。
- `linkAddr: pending` → 地址有了、只是你这台电脑验不通，先拿手机流量自己点开确认。
