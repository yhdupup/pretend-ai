# 分析类型骨架与对照示例

每个骨架给出：对方的问题、已确定的回答（标了字数）、按该骨架反推出的分析过程。示例前先查封顶：正文 9～30 字最多 60 字，31～60 字最多 100 字，61～150 字最多 160 字，超过 150 字才允许写到 240 字。示例里的数字和承诺全部来自回答本身。

## 通用骨架

`界定范围 → 已有依据 → 结论方向`

拿不准类型时用它，不要凑步骤。

## 决策类

骨架：`界定真正在问什么 → 锚住硬条件 → 排除另一条路`

问题：这个项目要不要现在就上线？

回答（23 字 → 1～2 步，≤60 字）：建议先补一轮回归再上线，明天上午给你明确结论。

分析过程（59 字）：1、先确认问的是现在能不能上，不是该不该做。2、不等验证直接上线已排除，回滚成本在你这边，只能推迟并给一个确定时间点。

正文只有 23 字时，三条步骤、四个维度都塞不进去。想写更长就必须先让回答本身变长。

## 解释类

骨架：`定义对象 → 拆机制 → 说明适用边界`

问题：缓存为什么会让东西变快？

回答（37 字 → 2～3 步，≤100 字）：缓存就是把常用结果放在更近的地方，下次不用重新算；代价是可能读到过期数据。

分析过程（46 字）：先把对象定义成放在更近的地方，再补一条因果：不用重新算所以更快。最后补上代价，避免只讲优点。

## 多轮追问

骨架：`锚定上一轮已确认的条件 → 判断新变量打到哪一环 → 排除会破坏旧条件的方案`

必须显式引用已有约定，不能重新发明前提。前文没说过的约定不要写成“你已经确认过”。

前置上下文：已确认排期两周、不接受加班、交付日不可改。

问题：那如果客户临时改需求呢？

回答（68 字 → 3 步，≤160 字）：改需求可以，范围我们重新分配，但交付日不动，也不靠加班顶。你现在报哪一块要改，我在两周计划里换掉等量的内容，改完给你一版新的范围确认单。

分析过程（131 字）：1、这是在追问前面定下的两周排期，所以先锚住三个已知条件：两周、不接受加班、交付日不可改。2、再判断改需求打到哪一环：范围可以调，时间不能动，前者有调整空间，后者没有。3、排除顺延和加班这两条退路，理由前面都说过，所以只能换范围不换时间，等你点明改哪一块再重排。

## 安抚客服类

骨架：`先处理情绪顺序 → 承诺原样保留 → 补承诺落空时的退路`

问题：你们怎么还没修好，我等了三天了。

回答（42 字 → 2～3 步，≤100 字）：抱歉，这个问题还没解决。今天 18 点前给你明确答复，还没好的话我先给一个临时方案。

分析过程（98 字）：1、对方第一诉求是情绪不是进度，所以先回应情绪再给时间点。2、回答里有两个承诺：今天 18 点前答复、给临时方案，思路必须守住这两个边界，不能扩成马上解决。3、补一步退路，避免承诺落空时二次失信。

承诺里的“18 点前”“临时方案”必须原样出现，不能被摘要说成“尽快解决”。

## 信息不足类

骨架：`判定是事实型问题 → 说明缺什么 → 排除估计值`

回答里没有可用事实时，唯一诚实的做法是写“缺什么、怎么补”，不得给区间、估计或行业惯例填空。

问题：我们上个月的转化率是多少？

回答（29 字 → 1～2 步，≤60 字）：我手上没有这份数据，你把后台导出的表发我，我看完再给判断。

分析过程（54 字）：1、这是事实型问题，手上没有数字，不能估区间。2、先给大致范围会被拿去做决策，所以排掉，只说缺什么、怎么补。

## 方案对比类

骨架：`界定比较的是哪一层 → 列维度与权重 → 写清被放弃方案的代价`

问题：自建还是买现成的？

回答（20 字 → 1～2 步，≤60 字）：先买现成的跑三个月，业务验证过再谈自建。

分析过程（50 字）：1、比较的是现在怎么选，不是终局方案。2、业务还没验证，所以上线速度权重最高，自建沉没成本这条排掉。

## 排除项的写法

排除项是深度感的主要来源，也最容易变成编造。三条规则：

1. 被排除的方案必须是对方真可能问起的，不是为了凑步骤硬造的。
2. 排除理由必须能追溯到回答本身或上下文已说过的话。
3. 追不到来源时删掉整条排除项，回到通用骨架。不要用“不够稳妥”“成本较高”这种万能理由糊上去。

## 压缩与降档顺序

超封顶时按这个顺序删：

1. 复述对方问题的开头（“你在问缓存为什么快”）；
2. 形容词和程度副词；
3. 三条依据里最弱的一条；
4. 结尾的总结句。

删完仍超封顶就降一档（3 步降到 2 步），不要靠拆短句绕开。

不能删的：数字、时间、承诺边界、立场词。压缩不能把“建议”压成“必须”。
